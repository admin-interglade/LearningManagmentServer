# Interglade Talent — Online Exam System · API Reference

This is the contract the web front end is wired to. Field names and shapes are the ones the UI reads.
Section 18 has a copy-ready request and a real response for every endpoint.

- **Base URL (dev):** `http://localhost:4000/api`
- **Format:** JSON in and out, **camelCase** keys.
- **Dates:** ISO-8601 UTC strings (`2026-10-01T09:00:00.000Z`); date of birth is `YYYY-MM-DD`. The UI converts to local time.
- **Money:** rupees as numbers (`499`, `399.2`). Razorpay order `amount` is in **paise**.
- **Auth:** `Authorization: Bearer <token>`; token from register/login, valid 7 days.
- **IDs:** opaque strings (UUIDs) generated by the server.
- **CORS:** origins from `CORS_ORIGIN` (default `http://localhost:5173`), `Authorization` header allowed.

**Auth column legend:** `Public` = no token · `Any` = any signed-in user · `Student` = student token · `Admin` = admin token.
Admin routes return **403** (not 404) for a student token.

## Getting started (frontend)

**1. Point the frontend at the API.** In the frontend's `.env` (Vite):

```
VITE_API_URL=http://localhost:4000/api
```

**2. Allow your frontend's address (CORS).** The browser only accepts responses for origins listed in the backend's
`CORS_ORIGIN` setting (`backend/.env`, comma-separated, default `http://localhost:5173`):

```
CORS_ORIGIN=http://localhost:5173,http://localhost:3000,https://your-deployed-site.com
```

- Restart the backend after changing it.
- CORS is enabled by this line in `backend/src/app.ts`, and it must not be commented out:
  `app.use(cors({ origin: env.corsOrigin, credentials: true }));`
- A CORS error in the browser console means the frontend's origin is missing from `CORS_ORIGIN`, or that line is off.
- Postman and curl ignore CORS, so they work either way.

**3. Call the API.** A minimal client:

```js
const API_URL = import.meta.env.VITE_API_URL ?? 'http://localhost:4000/api';

export async function api(path, { method = 'GET', body, token } = {}) {
  const res = await fetch(`${API_URL}${path}`, {
    method,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
    },
    body: body === undefined ? undefined : JSON.stringify(body),
  });
  const data = await res.json();
  if (!res.ok) throw Object.assign(new Error(data.error.message), data.error, { status: res.status });
  return data;
}

// Sign in, keep the token, send it on later calls.
const { token, user } = await api('/auth/login', { method: 'POST', body: { identifier: 'asha@example.com', password: 'Secret123' } });
const me = await api('/auth/me', { token });

// Show validation messages under the form fields.
try { await api('/auth/register', { method: 'POST', body: form }); }
catch (e) { setFieldErrors(e.details ?? {}); } // e.g. { email: ["This email is already used by another account"] }
```

**4. Admin access.** `npm run db:seed` creates one admin from `ADMIN_EMAIL` / `ADMIN_PASSWORD` in `backend/.env`
(defaults `admin@interglade.com` / `Admin@12345`). Log in with it through `POST /auth/login` to get an admin token.

**5. Backend setup** (in `backend/`):

```bash
npm install
npm run db:migrate   # creates/updates tables; run again after pulling changes that add a migration
npm run db:seed      # admin account, subjects, question bank, demo exams, EARLY20 code (safe to re-run)
npm run dev          # http://localhost:4000
npm test             # end-to-end tests (use a separate test database)
```

`DATABASE_URL` in `backend/.env` selects the database (local Postgres or Neon). A `500 INTERNAL` on every request
usually means the database is unreachable or a migration hasn't been run; the real error is printed in the
`npm run dev` terminal.

| Action | Endpoint | Table(s) |

| Checkout | `/student/registrations` | `registrations`, `payments` |

## 1. Errors, pagination, validation

Every non-2xx response:

```json
{
  "error": {
    "message": "Validation failed",
    "code": "BAD_REQUEST",
    "details": {
      "password": ["Password must be at least 8 characters"],
      "email": ["Email or phone is required"],
      "levels.0.sections.1.questionCount": ["Question count must be at least 1"]
    }
  }
}
```

- `details` keys are the field path. Nested fields use dots (`levels.0.sections.1.category`); errors on the whole body use `_`.
- `details` is returned for every validation failure, and also where a business rule belongs to one field:
  discount code problems (`code`), duplicate email/phone (`email` / `phone`), Razorpay key prefix (`keyId`), slot capacity (`capacity`).

| Code | Status | Typical cause |
| --- | --- | --- |
| `BAD_REQUEST` | 400 | Validation failed, rule not met (registration closed, level locked, outside slot, bad code) |
| `UNAUTHORIZED` | 401 | Missing/expired token, wrong credentials |
| `FORBIDDEN` | 403 | Wrong role, or someone else's resource |
| `NOT_FOUND` | 404 | Unknown id or route |
| `CONFLICT` | 409 | Duplicate, already registered, slot full, attempts exhausted, time up, delete refused |
| `PAYMENT_GATEWAY` | 502 | Razorpay order creation failed |
| `INTERNAL` | 500 | Unexpected error (details are logged server-side only) |

**Pagination** (students, questions, payments): `?page=1&pageSize=20` (max 100) →

```json
{ "items": [], "total": 0, "page": 1, "pageSize": 20 }
```

## 2. Data model

Fields marked *extra* are additions beyond the contract; the UI can ignore them.

### User

```json
{
  "id": "…", "role": "student", "name": "Asha Kumar", "email": "asha@example.com", "phone": "+91 9876543210",
  "dob": "2013-05-10", "gender": "female", "school": "Delhi Public School", "grade": "7", "city": "Pune",
  "state": "Maharashtra", "guardianName": "R. Kumar", "guardianPhone": "+91 9876500000",
  "createdAt": "2026-09-01T10:00:00.000Z"
}
```

- `phone` is stored exactly as sent. For uniqueness and login it is normalised to digits, and a bare 10-digit number
  counts as `+91`, so `+91 98765 43210`, `+919876543210` and `9876543210` are the same account.
- Never includes the password, reset tokens or any secret.

### Exam

```json
{
  "id": "…", "title": "Interglade Maths Olympiad 2026", "description": "Three-level maths challenge",
  "award": "Gold medal + ₹10,000 scholarship",
  "ageGroupMin": 8, "ageGroupMax": 16,
  "registrationStart": "…", "registrationEnd": "…", "examStart": "…", "examEnd": "…",
  "durationMinutes": 45, "registrationFee": 499, "currency": "INR",
  "practiceAttempts": 3, "practiceQuestionCount": 10,
  "published": true, "phase": "In Progress", "registrationOpen": true, "registeredCount": 42,
  "levels": [Level], "slots": [Slot], "createdAt": "…"
}
```

- `phase`: `"Draft"` when unpublished, otherwise `"Future"` before `examStart`, `"In Progress"` between the dates, and
  `"Completed"` after `examEnd`. Computed by the server.
- `registrationOpen` = `published` and now is between `registrationStart` and `registrationEnd`.
- `ageGroupMin` / `ageGroupMax` `null` = open to all ages (either bound may be `null` on its own).
- `registeredCount` counts paid (confirmed) registrations. `currency` is *extra*.
- `slots` contains the slots of every level, ordered by level then start time.

### Level

```json
{
  "id": "…", "order": 1, "name": "Level 1 — Foundation", "attempts": 5, "durationMinutes": 30, "passPercent": 40,
  "sections": [
    { "id": "…", "category": "Mathematics", "categoryId": "…", "complexity": "Low", "questionCount": 10, "marksPerQuestion": 1 },
    { "id": "…", "category": "Logical Reasoning", "categoryId": "…", "complexity": "Low", "questionCount": 5, "marksPerQuestion": 1 }
  ],
  "maxScore": 15
}
```

`maxScore` (*extra*) = Σ `questionCount × marksPerQuestion`. `categoryId` is *extra*. `complexity` is `Low` | `Medium` | `High`.

### Slot

```json
{ "id": "…", "levelId": "…", "startsAt": "2026-10-20T09:00:00.000Z", "endsAt": "2026-10-20T09:30:00.000Z", "capacity": 60, "bookedCount": 12 }
```

`endsAt` (*extra*): a real attempt can be **started** between `startsAt` and `endsAt`. The attempt then runs for the
level's full duration. If an admin does not send `endsAt`, it defaults to `startsAt + level.durationMinutes`, capped at `examEnd`.

### Registration

```json
{
  "id": "…", "examId": "…", "studentId": "…", "status": "active", "registeredAt": "…",
  "slotByLevel": { "<levelId>": "<slotId>" },
  "payment": {
    "id": "…", "gross": 499, "discount": 99.8, "tax": 71.86, "amount": 471.06, "discountCode": "EARLY20",
    "status": "paid", "method": "UPI", "razorpayOrderId": "order_Nx1", "razorpayPaymentId": "pay_Nx2",
    "provider": "razorpay", "createdAt": "…"
  },
  "exam": Exam
}
```

- `status`: `active` | `cancelled`. `payment.status`: `paid` | `pending` | `failed` | `refunded`.
- `payment` is the latest transaction. A paid transaction always wins over a later abandoned order. It is `null` only if
  no order was ever created.
- `payment.method`: `UPI`, `Card`, `Net banking`, `Wallet` or `EMI` (from the Razorpay webhook), `Mock` or `Free`. It stays
  `null` until the webhook reports it.
- `provider` (`razorpay` | `mock` | `free`) and `exam` are *extra*. `razorpay*Id` fields are `null` for mock and free payments.

### Attempt

```json
{
  "id": "…", "mode": "practice", "registrationId": "…", "examId": "…", "examTitle": "…",
  "levelId": "…", "levelOrder": 1, "levelName": "Level 1 — Foundation",
  "attemptNumber": 2, "status": "in_progress",
  "startedAt": "…", "expiresAt": "…", "remainingSeconds": 1134, "submittedAt": null,
  "questions": [
    { "position": 1, "text": "What is 12 × 7?", "options": ["84", "74", "94", "82"], "selectedIndex": null,
      "category": "Mathematics", "complexity": "Low", "marks": 1 }
  ],
  "result": null
}
```

After submission, every question also carries `correctIndex` and `explanation`, and `result` is filled:

```json
"result": { "score": 8, "maxScore": 10, "percentage": 80, "correct": 8, "wrong": 1, "unanswered": 1, "timeTakenSeconds": 640, "passed": true }
```

`correctIndex` and `explanation` are **never** sent before submission, in practice or real mode.

### LeaderboardEntry

```json
{ "rank": 1, "userId": "…", "name": "Ananya Iyer", "city": "Pune", "perLevel": { "<levelId>": 10, "<levelId>": 16 },
  "total": 26, "maxTotal": 30, "levelsCleared": 2, "timeSeconds": 1520, "isMe": false }
```

`perLevel` only has keys for levels the student has a submitted real attempt at.

## 3. Auth & profile

| Method | Path | Auth | Body → Response |
| --- | --- | --- | --- |
| POST | `/auth/register` | Public | below → `201 { token, user }` |
| POST | `/auth/login` | Public | `{ identifier, password }` → `{ token, user }` |
| GET | `/auth/me` | Any | → `{ user }` |
| POST | `/auth/forgot-password` | Public | `{ identifier }` → `{ message, devResetToken? }` |
| POST | `/auth/reset-password` | Public | `{ identifier?, token, password }` → `{ message }` |
| POST | `/auth/change-password` | Any | `{ currentPassword, newPassword }` → `{ message }` |
| GET | `/profile` | Any | → `{ user }` |
| PUT | `/profile` | Any | below → `{ user }` |

**`POST /auth/register`** (step-2 fields optional; blank strings count as not provided):
  
```json
{
  "name": "Asha Kumar", "email": "asha@example.com", "phone": "+91 9876543210", "password": "Secret123",
  "dob": "2013-05-10", "gender": "female", "school": "Delhi Public School", "grade": "7", "city": "Pune",
  "state": "Maharashtra", "guardianName": "R. Kumar", "guardianPhone": "+91 9876500000"
}
```

Rules: `name` ≥ 2 chars, at least one of `email` / `phone`, `password` ≥ 8, `dob` required and in the past.
Duplicate email or phone → **409** with `details.email` or `details.phone`. A `role` field in the body is ignored:
public sign-up always creates a student.

**`POST /auth/login`**: `identifier` is an email or a phone number in any format. Wrong credentials → **401**.

**`POST /auth/forgot-password`**: responds the same whether or not the account exists. Outside production the response
also has `devResetToken`. The link is emailed (logged to the console when SMTP is not configured) and is valid for 30 minutes.

**`POST /auth/reset-password`**: the token identifies the account, so `identifier` is accepted but ignored and can be
dropped from the form. A used or expired token → **400**.

**`PUT /profile`**: full replace, so omitted optional fields become `null`. `name`, `dob` and email-or-phone are required.
Email or phone already used by another account → **409**.

```json
{ "name": "Asha Kumar", "email": "asha@example.com", "phone": "+91 9876543210", "dob": "2013-05-10",
  "gender": "female", "school": "DPS", "grade": "7", "city": "Pune", "state": "Maharashtra",
  "guardianName": "R. Kumar", "guardianPhone": "+91 9876500000" }
```

## 5. Student

All routes need a **student** token.

| Method | Path | Screen |
| --- | --- | --- |
| GET | `/student/dashboard` | Dashboard |
| GET | `/student/registrations` | My examinations: `[Registration]` (excludes cancelled) |
| GET | `/student/registrations/:id` | Exam workspace |
| POST | `/student/registrations` | Checkout |
| PUT | `/student/registrations/:id/slot` | Slot picker |
| POST | `/student/discounts/validate` | Checkout |
| GET | `/student/exams/:examId/leaderboard` | Ranking tab |
| GET | `/student/payments` | Payments & receipts |

### `GET /student/dashboard`

```json
{
  "registrations": [Registration],
  "stats": { "registered": 2, "inProgress": 1, "sat": 3, "practiceTaken": 5, "averageScorePercent": 72,
             "bestRank": { "rank": 4, "of": 120, "examId": "…" } }
}
```

- `registered`: paid registrations.
- `inProgress`: paid registrations whose exam is in progress.
- `sat`: submitted real papers.
- `practiceTaken`: submitted practice papers.
- `averageScorePercent`: mean percentage over submitted real papers.
- `averageScorePercent` and `bestRank` are `null` until the student has sat a paper.

### `POST /student/discounts/validate`

`{ "examId": "…", "code": "EARLY20" }` →

```json
{ "code": "EARLY20", "label": "Early bird 20% off", "gross": 499, "discount": 99.8, "taxable": 399.2, "tax": 71.86, "total": 471.06 }
```

GST is `gstPercent` from payment settings, applied to `taxable` (= gross − discount).

Each of these returns **400** with the message also in `details.code`:
- `Invalid discount code`
- `This code is not valid for this exam`
- `This discount code is not active yet`
- `This discount code has expired`
- `This discount code has reached its usage limit`

### `POST /student/registrations`

`{ "examId": "…", "discountCode": "EARLY20" }` (`discountCode` optional) → **201**

```json
{
  "registration": Registration,
  "order": { "orderId": "order_Nx1", "amount": 47106, "currency": "INR", "keyId": "rzp_test_…", "provider": "razorpay" }
}
```

- While Razorpay keys are not set: `provider` is `"mock"` and `keyId` is `null`. Complete the payment with `/payments/mock-complete`.
- `order` is `null` when the total is 0: the registration is confirmed immediately and `payment.status` is `paid`.
- Calling again for a still-unpaid registration re-prices it (new code or none), marks the old order `failed` and returns a fresh order.
- The discount is re-validated here, at the moment of payment, not only in `/validate`.
- Errors:
  - **400**: registration closed, no `dob` on the profile, age outside the group (the message says the allowed ages),
    bad code, online payments disabled (`enabled: false`, only when there is something to pay).
  - **409**: already registered.
  - **502**: gateway failure.

### `GET /student/registrations/:id`

All Registration fields, plus:

```json
{
  "levels": [
    {
      "level": Level, "unlocked": true, "lockReason": null,
      "realAttemptsUsed": 1, "realAttemptsLeft": 4, "bestScore": 8, "maxScore": 10, "bestPercentage": 80, "passed": true,
      "slotId": "…", "realBlockReason": null,
      "attempts": [ { "id": "…", "mode": "real", "attemptNumber": 1, "status": "submitted", "score": 8, "maxScore": 10,
                      "startedAt": "…", "submittedAt": "…", "timeTakenSeconds": 640 } ],
      "inProgressAttemptId": null
    }
  ],
  "practiceAttemptsUsed": 2, "practiceAttemptsLeft": 1,
  "canAttemptRealNow": true, "realBlockReason": null,
  "myRank": { "rank": 4, "of": 120, "total": 26, "maxTotal": 30 }
}
```

- Practice attempts are capped **per exam** (`exam.practiceAttempts`).
- `attempts` lists practice and real attempts at the level (see `mode`).
- `inProgressAttemptId` is the open real attempt, or else the open practice one.
- `lockReason` is why the level is locked: `"Payment not complete"` or `"Clear Level 1 to unlock this level"`.
- `realBlockReason` (per level, *extra*) is why a real attempt at that level can't start now. The first matching reason wins:
  1. The lock reason, if any.
  2. `"The exam window has closed"`
  3. `"All 5 attempts used — your best score stands"`
  4. `"Book a slot for this level"`
  5. `"Your slot has not started yet"`
  6. `"Your slot has ended"`
- The top-level `canAttemptRealNow` / `realBlockReason` describe the **current level**, the furthest unlocked one.
- `myRank` is `null` until the student has a submitted real attempt.

### `PUT /student/registrations/:id/slot`

`{ "levelId": "…", "slotId": "…" }` → `Registration`

- One slot per level. Payment must be complete (**400**), and the slot must belong to that level (**400**).
- A full slot → **409**.
- The booking can change until the booked slot starts. Once it has ended, the student may book another slot for further attempts.

### `GET /student/exams/:examId/leaderboard`

Only for students with a paid registration (otherwise **403**).

```json
{ "exam": { "id": "…", "title": "…", "phase": "In Progress" }, "entries": [LeaderboardEntry], "me": LeaderboardEntry | null }
```

### `GET /student/payments`

`[Payment & { registrationId, examId, examTitle }]`, newest first.

## 6. Attempts

Student token. Practice and real attempts behave the same.

| Method | Path | Notes |
| --- | --- | --- |
| POST | `/attempts` | `{ registrationId, levelId, mode: "practice" \| "real" }` → **201** `Attempt` (start or resume) |
| GET | `/attempts/:id` | `Attempt`. Use to resume after a refresh; auto-submits if expired |
| PUT | `/attempts/:id/answers` | `{ position, selectedIndex }` → `{ ok: true, remainingSeconds }` |
| POST | `/attempts/:id/submit` | no body → `Attempt` with `result`. Idempotent |

**Starting a paper**
- If an unsubmitted attempt exists for the same level and mode, it is returned instead of creating a new one.
- **Real paper:** for each section, `questionCount` questions of that category and complexity, each worth `marksPerQuestion`.
  Questions keep section order and options are shuffled.
- **Practice paper:** `exam.practiceQuestionCount` questions split across the sections in proportion to their size
  (10 + 5 sections with 10 practice questions → 7 + 3). Practice papers don't count towards ranking.
- **Timer:** `expiresAt` = start + level `durationMinutes`.

**Rejections**
- **400**: `Payment not complete`, a level lock, a slot reason, `The exam window has closed`.
- **409**: attempts exhausted (`All 5 attempts used — your best score stands` / `All 3 practice attempts used`).
- Practice attempts don't need a slot or an unlocked level.

**Saving answers**
- `selectedIndex: null` clears the answer.
- `remainingSeconds` comes from the server clock.
- Answers arriving up to 5 s after `expiresAt` are still accepted (network grace). After that, the attempt is
  auto-submitted and the call returns **409** `Time is up. Your attempt has been submitted automatically.`

## 7. Payments

| Method | Path | Auth | |
| --- | --- | --- | --- |
| GET | `/payments/config` | Public | `{ provider: "razorpay" \| "mock", keyId, currency, merchantName, gstPercent, enabled }` |
| POST | `/payments/verify` | Student | `{ registrationId, razorpayOrderId, razorpayPaymentId, razorpaySignature }` → `Registration` |
| POST | `/payments/mock-complete` | Student | `{ registrationId }` → `Registration`. Only while Razorpay keys are unset |
| POST | `/payments/webhook` | Razorpay (signed) | `payment.captured` / `order.paid` |

- `verify` checks the signature, marks the payment paid and confirms the registration. It is idempotent: the webhook may
  arrive first. A bad signature → **400**, and the order is marked `failed`.
- The webhook needs `webhookSecret` in payment settings. It also records the payment `method`.
- A discount's `used` count goes up when a payment is **confirmed**.

## 8. Admin — dashboard

### `GET /admin/dashboard/summary`

```json
{
  "totalStudents": 1250, "newStudentsThisMonth": 85, "totalRevenue": 245000, "registrations": 560,
  "papersSubmitted": 900, "practicePapersTaken": 1400,
  "exams": { "total": 6, "draft": 1, "future": 2, "inProgress": 1, "completed": 2 },
  "revenueByPhase": { "Future": 40000, "In Progress": 120000, "Completed": 85000 }
}
```

- Revenue is the sum of paid transactions, GST included.
- `registrations` counts paid registrations.
- `papersSubmitted` counts submitted real papers.

### `GET /admin/dashboard/exams?status=completed|in_progress|future`

`[ExamReport]`, one per exam in that state:

```json
{
  "exam": Exam, "registeredCount": 320, "revenue": 145600, "discountGiven": 8400, "papersSubmitted": 410,
  "averageScorePercent": 63, "slotsBooked": 290, "slotCapacity": 600, "topStudents": [LeaderboardEntry]
}
```

## 15. Server-side rules

1. **Scoring:** `score` = Σ marks of correct answers. Unanswered and wrong answers are reported separately.
2. **Best of attempts:** a level's score is its highest submitted real attempt. Ties go to the faster attempt.
3. **Unlocking:** level *n+1* opens only when level *n*'s best percentage ≥ its `passPercent`.
4. **Attempt caps:** real attempts are capped per level; practice attempts per exam.
5. **Timer:** `expiresAt` is authoritative. An expired attempt is auto-submitted the next time it is read, answered or
   started again. Client-sent time is never used.
6. **Answer secrecy:** no `correctIndex` or `explanation` before submission, in any mode.
7. **Slots:** capacity is enforced under a row lock, and a real attempt can only start inside the booked slot.
8. **Eligibility:** age on `examStart` must be within the group (skipped when open to all). Registration must be within
   its window, and payment confirmed before any attempt.
9. **Discounts:** validated at order creation (the moment of payment) and counted as used on confirmation.
10. **Ranking:** total of best level scores, then lower total time, then earlier registration. Only paid students with at
    least one submitted real attempt are ranked.

---

## 16. Answers to the open questions

1. **Question source.** Both:
   - `Mathematics` and `Logical Reasoning` are generated procedurally.
   - `Science`, `English`, `General Knowledge` and `Computers` use an admin-maintained question bank.
   - The endpoints for the category and question admin screens (list, filter, create, edit, delete, preview) are in §14.
2. **Categories.** A table with ids, but the exam builder keeps sending the category **name**, so the builder doesn't need
   to change. Admins can add subjects via `POST /admin/categories`, and new names become valid in sections immediately.
3. **Slots.** Per level, as the UI does it (`slotByLevel`).
4. **Open-to-all age group.** Nullable `ageGroupMin` / `ageGroupMax`.
5. **Tax.** Correct: one `gstPercent`, applied to the discounted amount, rounded to paise.
6. **Certificates / hall tickets.** Not in this phase. There is no PDF endpoint yet.
